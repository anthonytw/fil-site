NAME

fil - A remote shell that keeps your place: reconnect, detach and reattach

SYNOPSIS

fil [-L SPEC]... [-R SPEC]... [-D SPEC]... [-A|-a] [--transport MODE] [--config FILE] HOST [SESSION]
fil COMMAND ...

DESCRIPTION

A remote shell that keeps your place: reconnect, detach and reattach

OPTIONS

-L <SPEC>
Listen here, connect from the host: [BIND:]PORT:HOST:HOSTPORT, or PORT for the same port on the host's localhost. A bare port binds loopback; * or an empty BIND is every interface. Repeatable
-R <SPEC>
Listen on the host, connect from here: [BIND:]PORT:HOST:HOSTPORT, or PORT for the same port on this machine's localhost (not ssh's reverse SOCKS proxy). PORT 0 asks the host for a free port. Repeatable
-D <SPEC>
A SOCKS proxy here that connects from the host: [BIND:]PORT. Repeatable
-A
Relay your ssh-agent to the session while you are attached (the config's agent = "confirm" stays "confirm")
-a
Do not relay the agent, whatever the config says (the last of -A and -a wins, as in ssh)
--transport <MODE>
How to reach the host: auto (the pipe first, then QUIC), pipe (ssh only) or direct (QUIC once attached)

Possible values:

  • auto
  • pipe
  • direct
--predict <MODE>
Predictive echo for this run, over the config's predict setting: off, adaptive (the default: guesses shown only on a slow link) or always

Possible values:

  • off
  • adaptive
  • always
--config <FILE>
Read this config file instead of ~/.config/fil/config.toml ($FIL_CONFIG also works)
-h, --help
Print help
<HOST>
The host: a name or alias for ssh, user@name, or a name from your config
[SESSION]
The session to attach to; it is created if it does not exist

COMMANDS

fil ls

List the sessions on HOST

Usage: fil ls [OPTIONS] <HOST>

fil kill

End a session: its shell and everything it started are killed

Usage: fil kill [OPTIONS] <HOST> <SESSION>

fil detach

Detach whoever is attached to a session; it keeps running (inside a session, with no arguments: this one)

Usage: fil detach [OPTIONS] [HOST] [SESSION]

fil forward

Add a forward to a running session, or remove one. The attached client asks its user before it listens or connects for a forward added this way

Usage: fil forward [OPTIONS] [HOST] [SESSION]

HOST
The host the session runs on. Left out inside a session: the session is $FIL_SESSION
SESSION
The session (default: main)
-L SPEC
Add: listen on this machine, connect from the host (same spec as the attach flag)
-R SPEC
Add: listen on the host, connect from this machine
-D SPEC
Add: a SOCKS proxy on this machine
--rm PORT
Remove the forward that listens on PORT. If a -L and a -R share the port, say which with the flag instead: --rm -L PORT

fil ports

Show what is listening on the host and what is forwarded, with the process behind each

Usage: fil ports [OPTIONS] [HOST] [SESSION]

HOST
The host to ask. Left out inside a session: this machine's daemon, for this session
SESSION
Only this session
--json
Print JSON (schema 1) instead of the table
--probe
Also probe the listeners no fil session started (by default only the -L targets and the sessions' listeners are). Such a listener is often a tunnel, and the probe reaches whatever it leads to; a known forwarder (ssh, kubectl, ...) is never probed

fil server

The remote side: run by the pipe command on the host, not by people

Usage: fil server --stdio

--stdio
Relay this process's stdin and stdout to the daemon (starting it if needed)

fil install

Install this fil on HOST over ssh, into ~/.local/share/fil (or check what is there, or remove what fil installed)

Usage: fil install [OPTIONS] <HOST>

HOST
The host: a name or alias for ssh, or user@name
--check
Show what is installed on HOST, and the fil on its PATH; change nothing
--remove
Remove the copies fil installed on HOST (not one in use by a running daemon)
--binary FILE
Upload this file instead of the bundled or this fil's own binary (it must be a release build for the host)

fil config

Look at the configuration

Usage: fil config [OPTIONS] <COMMAND>

fil config show

Show the settings that apply to HOST and where each value comes from (the default, [defaults] or [host.NAME]), like ssh -G. Reads only the config file; never contacts the host

Usage: fil config show [OPTIONS] <HOST>

NOTES

Examples:


  fil devbox                 attach to (or create) session "main" on devbox


  fil devbox build           attach to session "build"


  fil ls devbox              list the sessions on devbox


  fil kill devbox build      end session "build"


  fil detach devbox build    detach whoever is attached to "build"

Inside a session, type ~. after a newline to detach; ~? lists the escapes.

Configuration: ~/.config/fil/config.toml (see fil-config(5), or fil config show HOST). Logs: ~/.local/state/fil/client.log (set FIL_LOG=debug for more).

Exit status: 0 on a normal end (detached, or the session ended with nothing to report); the shell's own status if it exited with one; 128+N if the shell was killed by signal N or fil was stopped by signal N; 1 on an error or if the session was taken over, replaced or detached elsewhere; 2 on a usage error; 255 if a forward failed and forward_failure = "exit".

Source: every release publishes fil-<version>-source.tar.gz beside the binaries (GPL-3.0 Corresponding Source).
